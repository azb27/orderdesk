Instructions for Claude Code working in this repo. Read `SPEC.md` first; it is the plan of record. The current phase is the first unchecked box in SPEC §7.

## What this is
Orderdesk: WhatsApp orders (text and photos, four language styles) turned into draft sales orders for a fictional Dubai distributor, confirmed by an order-taker in a React console and posted to an ERP. The portfolio value is the **working product**, the **eval**, and the **engagement documents**.

## Commands
```bash
make setup                      # python deps (api/), npm ci (web/), local Postgres in .pg/ on port 5433
make db                         # migrate + seed the local database (once)
make world                      # generate catalogue, customers, history, eval messages + images (deterministic)
make test                       # pytest (needs the local Postgres) + vitest
make lint                       # ruff + tsc + oxlint
make dev                        # API on :8000 (worker in-process) + Vite on :5173
make e2e                        # Playwright against a running dev stack
docker build -t orderdesk-demo . # the public demo image (world + confidence model, never data/eval); deploy: docs/deploy.md
```
Install the secret guard once per clone: `ln -sf ../../scripts/pre-commit .git/hooks/pre-commit`. API keys live in an untracked env file, never in the repo.

## Hard rules
1. **The LLM never produces an id, a price, a quantity conversion or a total.** It extracts what the customer wrote and chooses among candidate SKU ids it was given (or NONE). Everything numeric is computed in code. Validate every model output against its schema and the candidate list; reject, don't repair.
2. **Ground truth lives in `data/eval/truth/` and is read only by `api/tests/` and `api/evals/`.** The parser, retrieval and generator-facing alias tables must never import it. Held-out street names never enter the catalogue alias table.
3. **No order reaches the ERP without a human confirmation** (role-checked on the server). The model never sends free-form text to a customer; replies are templates.
4. **Webhooks are verified and idempotent.** Unsigned or badly signed POSTs are rejected; a repeated message id is a no-op.
5. **Postgres is the only state.** No in-memory queues that lose work on restart. Open sessions per request; the worker uses `FOR UPDATE SKIP LOCKED`.
6. **Numbers in docs come from runs.** Results files are generated by scripts, with the command above each table. Discovery-brief figures are labelled as fiction.
7. **Frontend:** TypeScript strict, no `any`. Plain CSS with tokens in `web/src/styles/tokens.css`; logical properties (`margin-inline-start`) so Arabic renders right-to-left; every interactive element reachable by keyboard and labelled.
8. Record decisions that would be expensive to reverse as ADRs in `docs/adr/`.

## Conventions
- Python 3.11+, type hints, ruff (pinned), pytest. Seeds from `orderdesk.config.SEED`.
- Money is integer fils (1 AED = 100 fils) in code and the database; format only at the edge.
- Quantities are stored in base units (pieces) with the unit the customer used kept alongside.
- Times are UTC in storage, Asia/Dubai in the UI.
- Small commits, one concern each, imperative mood. When a phase finishes: tick it in SPEC §7 with evidence.
